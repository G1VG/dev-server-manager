Manual Pain Points (Without System)

Engineered Solution (Dev Server Manager)

  • ✅ LVM Dynamic Storage: Grow partitions online with lvextend -r without unmounting.
  • ✅ Enforced Password Expiry: chage -d 0 forces immediate password change on login.
  • ✅ Verified Tarball Pipeline: tar -tzf integrity checks with 7-day retention prune.

Examiner Defense Point: Why check UID < 1000?

Debian/Ubuntu reserves UIDs 0–999 for system daemons. Rejecting deletion for UID < 1000 ensures critical system users (root, www-data, sshd) are never accidentally removed.

Features 6 – 8

Shared Git Repositories & Setgid (2775)

Zero-conflict collaboration using Linux sticky group permissions and bare repositories

05 / 13

1. The Setgid Bit (`2`)

Setting chmod 2775 /srv/repos forces any file or directory created within to inherit the group developers, regardless of the creator's primary group.

2. Bare Repositories

Created with git init --bare --shared=group. Omits a working tree to eliminate merge conflicts during remote git push operations.

3. Git Safe Directory

Configured with git config --system --add safe.directory '*' to prevent Git 2.35+ ownership mismatch errors across multi-user checkouts.

# How a developer clones and pushes to the shared server
git clone ssh://dev01@devserver/srv/repos/webapp.git
git commit -m "Feature commit" && git push origin main # Permitted with group write access
💡 Key Difference: ls -l shows directory metadata (4096 B); our script uses du -sh to calculate true disk block consumption across all Git packfiles.
Features 11 – 13

Enterprise Storage: LVM & Online Growing

Physical Volumes, Volume Groups, and zero-downtime online partition expansion

06 / 13

Physical Volume (PV)

Target disk (real /dev/sdb or 3GB loopback /var/lib/devserver/disk.img via losetup).

Volume Group (vg_dev)

Central pool. 50% → lv_repos, 30% → lv_backup. 20% left unallocated for online growth.

Online Grow Console

Expands mounted logical volume and ext4 filesystem instantly with lvextend -r -L +<mb>M.

# Growing the repositories partition by 500 MB while fully mounted
sudo lvextend -r -L +500M /dev/vg_dev/lv_repos
# Output: Size of logical volume vg_dev/lv_repos changed -> resize2fs executed online!
CRITICAL VIVA QUESTION: What does the -r flag do?

-r (or --resizefs) automatically invokes resize2fs in the background. Without -r, only the LVM block device grows, leaving the filesystem small and requiring manual unmount/resize.

Features 16 & 21

System Automation via Cron Engine

Modular, version-controlled scheduled tasks running under systemd cron

07 / 13

Why `/etc/cron.d/` vs `crontab -e`?

  • 🔹 Modular Deployment: Managed as a dedicated file (/etc/cron.d/devserver).
  • 🔹 Explicit User Column: Specifies root directly, avoiding user crontab collisions.
  • 🔹 Version Control Ready: Can be deployed cleanly via Git or Ansible.
  • 🔹 Systemd Integration: Managed via systemctl enable --now cron.
# /etc/cron.d/devserver schedule table
SHELL=/bin/bash
PATH=/usr/local/sbin:/usr/local/bin:/sbin:/bin

# 1. Telemetry & Alerts (Every 5 minutes)
*/5 * * * * root /opt/dev-server-manager/scripts/monitor.sh

# 2. Verified Backup (Daily at 02:00 AM)
0 2 * * * root /opt/dev-server-manager/scripts/backup.sh

# 3. Disk Cleanup (Sundays at 03:00 AM)
0 3 * * 0 root /opt/dev-server-manager/scripts/cleanup.sh
⚙️ Execution Safety: Environment variables (SHELL and PATH) are explicitly declared at the top of the file to guarantee deterministic command execution.

Features 18 & 19

Disaster Recovery & Backup Pipeline

Automated archive creation, header verification, retention, and sandboxed restore

09 / 13
PHASE 1

Comprehensive Packaging

Archives /srv/repos along with /etc/passwd and /etc/group to preserve numerical UID/GID mappings on recovery.

PHASE 2

Integrity Verification

Runs tar -tzf immediately after creation. Corrupt archives that fail decompression are auto-deleted with an error logged.

PHASE 3

Safe Sandbox Restore

Extracts to /tmp/restore_<time> to let the admin inspect trees safely without risking live production overwrites.

# Backup generation, verification, and 7-day retention prune
tar -czf "$BACKUP_DIR/backup_$(date +%F_%H%M%S).tar.gz" -C / srv/repos etc/passwd etc/group
tar -tzf "$file" >/dev/null 2>&1 && echo "Verified OK" || rm -f "$file"
find "$BACKUP_DIR" -name "backup_*.tar.gz" -mtime +7 -delete
EXAMINER TIP: Why not rsync? Tar creates immutable point-in-time timestamped snapshots that can be verified and moved off-site easily, whereas rsync only mirrors live trees.
Features 14 & 15

Automated Disk Hygiene & Storage Reclamation

Safe multi-tier pruning, cross-device boundary protection, and measurable space recovery

10 / 13

1. Tiered Pruning Rules

Purges /tmp (>7 days), /var/tmp (>30 days), and developer core dumps + swap files (*.tmp, *~) in /home.

2. Cross-Device Safety (`-xdev`)

Enforces find -xdev to prevent deletion from crossing filesystem boundaries into mounted repositories or NFS shares.

3. Log Compression & Metrics

Compresses logs >7 days with gzip -f, clears apt package cache, and computes freed space via df deltas.

# Measuring disk space before and after cleanup
before=$(df --output=used -k / | tail -1)
find /home -xdev -type f -name "core" -mtime +7 -delete
after=$(df --output=used -k / | tail -1)
echo "Space freed: $(( (before - after) / 1024 )) MB"
🛡️ Dry-Run Mode: Running cleanup.sh --dry-run previews matches through sed "s/^/ would delete: /" without executing deletions.
Web Console

Flask Web Console: Security & Architecture

Zero-overhead REST backend, localhost binding, and command auditor drawer

11 / 13

Localhost Binding

Strictly bound to 127.0.0.1:5000. Remote access requires an authenticated SSH tunnel (ssh -L 5000:localhost:5000).

No Shell Injection

Uses subprocess.run(args, shell=False) exclusively. Metacharacters like ; or | cannot execute arbitrary code.

Binary Whitelist

Calls restricted to 25 approved binaries (useradd, lvextend, etc.). Blocks unauthorized binary execution.

Evaluator Feedback #1

Docker Dynamic Memory & LVM Storage

Runtime cgroups v2 memory scaling (zero downtime) and direct host LVM volume binding

13 / 15
DYNAMIC MEMORY

cgroups v2 Scaling

Containers start with --memory=512m and --memory-reservation=256m. Memory is scaled up or down live using docker update --memory without stopping active workloads.

LVM INTEGRATION

Direct LVM Binds

Host LVM partition /srv/repos (ext4 on lv_repos) is directly mapped: -v /srv/repos:/workspace/repos:rw. Container code inherits host setgid permissions and auto-expansion.

SANDBOX ISOLATION

Developer Sandboxes

Every developer gets an isolated Linux sandbox container with strict memory ceilings, preventing noisy-neighbor crashes on the host OS.

# Live dynamic memory scaling (kernel updates /sys/fs/cgroup/memory.max in microseconds)
sudo docker update --memory 1536m --memory-swap 3072m devserver-sandbox
# Output: devserver-sandbox memory updated online without dropping active shell or build
EXAMINER DEFENSE: How is LVM coupled with Docker? Rather than storing data in ephemeral Docker layers, container volumes are bound to the underlying LVM logical volume (lv_repos). When developers commit large files, our auto-disk system expands the LVM partition online while Docker runs.

Load Balancing & Auto Disk Management

High-availability Nginx proxy cluster and autonomous LVM auto-expansion with self-healing

Nginx High-Availability Load Balancer

PORT 8080

Fronts 3 backend Flask/Gunicorn worker instances (ports 5001, 5002, 5003) using the least_conn algorithm:

  • • Dynamic Least Connections: Routes requests to the worker with the fewest active jobs.
  • • Health Checks & Failover: max_fails=2 fail_timeout=10s isolates crashed nodes.
  • • Telemetry Header: X-Backend-Server reveals which node served each request.

Autonomous Auto Disk Management

CRON RUNNER

scripts/auto_disk.sh inspects partitions every 5 minutes with zero human intervention:

  • • Auto-Grow at 80%: Automatically runs lvextend -r -L +300M from pool free space.
  • • Self-Healing at 90%: Triggers emergency cleanup, docker image prune, and log gzip.
  • • Audit Trail: Records all [AUTO-GROW] events to /var/log/devserver/activity.log.
